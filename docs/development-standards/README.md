# Development Standards — Hallmark AI QA Automation Project

## Purpose

This folder defines the coding, workflow, and review standards for the Hallmark AI QA Automation project. It exists to keep contributions consistent, maintainable, and aligned with Hallmark's engineering practices — specifically tailored to the needs of QA Automation work (test frameworks, fixtures, supporting API/DB code, and Playwright suites).

## Documents Included

| File | Description |
|---|---|
| [`development-rules.md`](./development-rules.md) | Coding standards for HTML/CSS/JS, Node.js/Express, MySQL, Playwright, file naming, and error handling. |
| [`git-workflow.md`](./git-workflow.md) | Branch naming, commit message format, and the end-to-end feature development workflow. |
| [`code-review-checklist.md`](./code-review-checklist.md) | Checklists covering Frontend, Backend, Database, Manual Testing, API Testing, and Playwright review criteria. |

## Usage

- **Before starting work:** Read `development-rules.md` to follow the correct conventions for the area you're working in.
- **When creating a branch or PR:** Follow `git-workflow.md` for branch naming, commit messages, and the review/merge process.
- **When reviewing a PR:** Use the relevant section(s) of `code-review-checklist.md` based on what the change touches (frontend, backend, database, tests).
- These standards apply to all contributors on the QA Automation project, including engineers, reviewers, and new team members onboarding.
- Documents should be treated as living references — propose updates via PR (tagged `docs/`) following the same workflow as any other change.
